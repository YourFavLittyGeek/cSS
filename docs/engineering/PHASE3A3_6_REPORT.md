# Phase 3A.3–3A.6 — Expert ground-truth protection (roles, consensus, adjudication, provenance, missed lesions, bypasses, migration)

Not installed or activated; not committed (proposed commit below). Synthetic, isolated tests only. Builds on 3A.1 (`09b4424`) and 3A.2 (`d8244ec`, `9767548`).

## What was implemented
| Area | Implementation |
|---|---|
| Roles & permissions | New `scripts/review_roles.py`: roles expert / trainee / other / unknown (default unknown; never automatic); role administration and the separate adjudication permission need a typed phrase + administrator name + reason; append-only hash-chained history `review/project_roles_events.jsonl`. Reviewer windows cannot change roles or the policy (`/api/primary` refused). |
| Consensus | `call_ledger.py` call-policy/2.0: consensus of designated experts with a quorum (default 1), or one reference expert (fallback none / consensus). Per candidate: resolved, adjudicated, disagreement, abstained (Unsure), unrecognised, insufficient (quorum), no_expert, missing. Newest-wins and "reviewer with newest fallback" refused; old 1.0 policy files read as consensus. Automatic primary reviewer removed. |
| Adjudication | Expert with the adjudication permission; reason required; definite call only; recorded in `review/<ID>_events_adjudication.jsonl` with every call seen; withdrawal recorded; reviewers' calls never changed. |
| Provenance | Every counted call gets a class from the reviewer journals: verified_blind_post_3A, historical_blinding_verified (documented verification, pinned to the exact calls verified), historical_blinding_unknown, historical_adjudicated, not_blind_post_3A (second look / AI visible / AI released in the app / unblinded legacy tool). Imported / inherited calls and confirmations of another reviewer's call are kept but never count as independent reviews (lineage carry-overs and fingerprint re-attachment of the reviewer's own call do count). Only verified / adjudicated classes are primary ground truth. |
| Shared file derived | `ID_calls.csv` holds resolved / adjudicated calls only; rebuild refused (previous derived files kept) when any reviewer file differs from its journal (`call_ledger.integrity`, `review_io.check_table`, read-only). Consolidation removed (refused even with the old phrase); restore kept. |
| Missed lesions | `review_web.py`: one journaled file per reviewer `review/<ID>_missed_by_<name>.csv`; delete = tombstone; ids from a study-wide counter (never reused); all inputs validated (points inside the image, shape, plane, slice, size, action, id); only own marks editable; pre-3A shared file kept byte-for-byte as `_missed_legacy.csv` (read-only); a shared file changed by another program kept aside (`_missed_external_<time>.csv`); `ID_missed.csv` is derived (same leading columns + context / read phase / source). Anonymous reads write nothing. |
| Whole-study review | `?wholestudy=1` / `mode=wholestudy`: no candidates, outlines, calls, scores or AI; marks tagged `context=whole_study`; `POST /api/wholestudy` records completion with the number of marks; whether the reviewer had seen detector output before is recorded (`detector_seen_before`). Reviewer File menu entry + banner. |
| Bypasses closed | App op `percival/missed_lesion` disabled. `review_css.py` saves only with `--reviewer NAME`, into that reviewer's journaled file (read phase `unblinded_legacy`), then rebuilds the derived file; without a name nothing is written. Ledger reads report journal mismatches; Percival withholds that study's labels. `labels/` tools untouched (later phase). |
| Training gating | `percival_gui.label_summary` / `_examples`: labels only from resolved / adjudicated candidates with an eligible class; unresolved → excluded with reasons (eligibility rules 1.4: NO_EXPERT, INSUFFICIENT_QUORUM, NOT_PRIMARY_GROUND_TRUTH, REVIEWER_NOT_EXPERT, REVIEW_NEEDS_REPAIR); disagreement always needs adjudication (no setting resolves it); historical/ earlier-project labels never primary; missed lesions go through the eligibility engine (role + provenance); Pensieve-only missed rows ignored. |
| Migration | New `scripts/review_migrate.py`: `plan` (read-only), `apply --confirm "MIGRATE REVIEWS"` (originals copied + sha256 manifest verified first; baseline journal events; historical classification recorded as historical_blinding_unknown with evidence and a "verification candidate" flag; legacy missed file preserved; policy file → 2.0; no roles assigned; idempotent), `rollback <time> --confirm "ROLL BACK MIGRATION"` (byte-identical restore, created files removed). |
| Administration | App API `/api/calls/{roles, role, adjudicator, adjudicate, withdraw_adjudication, verify_historical, policy}`; `app/calls_view.js` rebuilt (roles table, typed-confirmation prompts, consensus / reference rule, per-study resolution table, adjudication prompt); CLI `scripts/review_admin.py`. |
| Bug found and fixed in 3A.1 code | Journal replay could order records differently from the file when one write added several records not in text order (e.g. #10 before #9). Fixed (deterministic order recorded); regression test added. |

## Remaining limitations
- No authentication: roles, adjudication and verification are local declarations (typed confirmation + reason, append-only history).
- Unnamed pre-v5.4 shared calls can never become ground truth except by adjudication.
- Until the administrator designates experts, every candidate is unresolved (shared calls file empty, Percival has no labels) — intended, but a visible behaviour change; the migration plan reports it per study.
- The reviewer's journal / review log keep original candidate ids (provenance); local files are not confidential.
- `labels/` tools (expert_import, label_missed, consensus, study_meta) are not integrated (later dataset/labels phase).
- Whole-study search has a minimal entry (menu / URL); the app's Studies screen has no dedicated button.
- `check_viewer.py` (Playwright) and the headless-Chrome DOM checks cannot run on this Mac.
- One intermittent failure of the 3A.1 concurrency test was seen once in ~35 runs and could not be reproduced (the test now reports every failed request).
- Not installed: the live app still runs the earlier build; installation needs separate approval.
